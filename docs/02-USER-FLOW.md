# 02. 사용자 흐름과 화면 상태

이 문서는 `start-meeting.bat`으로 실행하는 개인 PC의 기본 운영 흐름을 설명한다. 마이크와 업로드 파일은 로컬 Whisper로 전사하고, 저장된 전사문은 Windows Codex CLI로 요약한다. [처리 구조](03-ARCHITECTURE.md) · [운영 방법](13-SECURITY-OPS.md)

## 시작

1. 서버 PC에서 Docker Desktop을 켜고 Tailscale 연결을 확인한다.
2. 저장소 루트의 `start-meeting.bat`을 실행한다. 앱과 Whisper 컨테이너, Windows의 Codex 브리지가 시작되고 브라우저에서 새 회의 화면이 열린다.
3. 기존 앱 계정으로 로그인한다. 첫 실행에는 Whisper 모델을 다운로드한다. Codex 로그인이 만료되면 서버 PC에서 `codex login`으로 다시 로그인한다.

## 접속
최초 한 번 기존 접속 토큰으로 소유자를 확인하고 아이디·비밀번호를 등록한다. 이후에는 아이디·비밀번호로 로그인하며 로그인 유지 선택 시 서버 재시작 후에도 최대 30일 접속한다. 공개 회원가입은 제공하지 않는다. 로그아웃·만료 시 재로그인하며, 백업 복원 후에는 계정을 유지하고 다시 로그인한다.

## 마이크 회의

1. **새 회의**에서 제목과 선택 사항인 주제를 입력한다. **로컬 Whisper 전사 · 마이크 녹음**을 선택하고 회의를 준비한다.
2. 사용할 장치를 선택하고 녹음 동의를 확인한 뒤 **마이크 녹음 시작**을 누른다. 원본 녹음과 전사는 동시에 진행된다. Whisper는 약 8초 분량의 음성을 처리해 확정 발언과 시각을 표시한다. Whisper 전사의 화자는 **화자 미정**으로 표시된다. 발언별 화자 수정은 해당 회의에 선택할 화자 라벨이 있을 때 사용할 수 있다.
3. **녹음 종료 및 저장**을 누른 뒤 **요약과 검토 → AI 요약 생성**을 누른다.

## 녹음 파일 업로드

1. **새 회의**에서 **녹음 파일 업로드 · AI 회의록**을 선택한다. M4A, MP3, WAV, FLAC, OGG, WebM 파일을 첨부한다. 최대 256 MiB와 회의당 전사 시간 한도가 함께 적용된다.
2. 제목을 확인하고 **업로드하고 회의록 만들기**를 누른다. 업로드가 끝나면 서버가 원본을 보관하고 전사와 요약을 차례로 실행한다. 회의 목록으로 이동했다가 돌아와도 처리 상태를 확인할 수 있다.
3. 실패한 단계에 따라 **전사 다시 시도** 또는 **요약 다시 시도**를 누른다. 요약을 다시 시도할 때는 이미 저장된 전사문을 사용한다.

## 주제별 사전으로 전사 교정

1. **주제와 용어 사전**에서 표준어와 별칭을 등록하고 승인한다. 회의를 만들거나 파일을 업로드할 때 해당 주제를 선택한다.
2. 전사가 끝나면 **요약과 검토 → AI 사전 교정 후보 확인**을 누른다. 제안을 확인한 뒤 **검토 후 적용**을 누르면 원문을 보존하며 표시 문장을 바꾼다.
3. 이미 요약이 있으면 **AI 요약 다시 생성**을 눌러 교정이 반영된 전사문으로 갱신한다.

## 결과 확인과 다운로드

요약 진행률은 완료된 전사 구간의 요약·통합·저장 단계를 기준으로 갱신된다. 같은 단계에서 응답을 기다리는 동안 진행률이 유지될 수 있으며, 수동 생성 화면에는 경과 시간도 표시된다. 저장된 결과에서 핵심 요약, 주제별 논의, 결정, 할 일을 확인한다. 회의 화면에서 **DOCX·HWP·PDF** 중 한 형식을 선택하고 **회의록 다운로드**를 누른다.

원본 음성은 서버 PC에서 전사하고 보관한다. 요약을 요청할 때는 Codex CLI가 전사 텍스트를 OpenAI에 전달한다. 기본 운영은 ChatGPT 계정의 Codex 한도를 적용한다.

## 화면

| 화면 | 현재 역할 |
|---|---|
| `/`, `/meetings` | 회의 목록·검색·제목 변경·삭제 |
| `/meetings/new` | 제목·주제 입력과 Whisper 마이크 회의·녹음 파일 업로드·녹음 전용 모드 선택 |
| `/meetings/:id/live` | 마이크 녹음, 파일 처리 상태, 전사·요약 검토, 재생, 회의록 다운로드 |
| `/topics` | 주제·용어·별칭 관리와 후보 승인·거절 |
| `/usage` | Codex 계정 사용량, 전사 시간, 녹음 보관 설정 |

## 발언 상태와 업데이트
- `PARTIAL`: 동일 provider sequence/event 식별자로 UI에서 덮어씀; DB 저장은 선택적/짧은 보관.
- `FINAL`: provider 최종 이벤트가 오면 원문을 1회 불변 저장.
- `CORRECTION_PENDING`: 비동기 LLM 검사 중; 기존 화면/녹음 영향 없음.
- `CORRECTED`: 승인/자동 적용 가능한 안전한 변경만 반영하며 원문 보존.
- `REVIEW_REQUIRED`: 중첩 발언, 모호한 고유번호, 화자 불확정 등.
- 사용자 수정 시 `revision`을 증가시키고 LLM의 늦은 응답이 덮어쓰지 않음.

## 예외
- 두 사람이 동시에 발언: 두 발언의 타임스탬프 중첩 가능; 완전 분리를 보장하지 않음.
- 말더듬: 텍스트 클린업은 표시 계층, 원문 저장.
- 전사 연결 장애가 발생해도 녹음 청크는 별도로 저장한다. 연결을 복구한 시점부터 자막을 다시 생성한다.
- 브라우저 종료/절전: 녹음 보존 범위는 브라우저 저장 구현과 운영체제 상태에 따라 다름; 한계 UI 고지.
- 전사 시간 한도에 도달하면 자막 생성을 멈추고, 마이크 녹음은 계속할 수 있다. Codex 한도로 요약이 실패하면 한도가 갱신된 뒤 다시 시도할 수 있다.

## 연결 실패와 녹음 재개 (2026-10-29)

- 상단은 AI 연결, 녹음 영역은 원본 보관·서버 업로드 상태다. 업로드 성공이 AI 연결 성공을 뜻하지 않는다.
- **AI 전사 다시 연결**을 누르면 마이크 녹음을 유지하며 새 전사 연결을 시도한다. 소켓 단절은 간격을 늘려 자동 재시도한다.
- 연결되지 않은 음성 구간은 현재 화면에 별도로 표시하며 자동 재전사하지 않는다. 이 구간 표시는 화면 상태로, 새로고침 후 유지하지 않는다.
- 새로고침은 마이크를 중단한다. 같은 브라우저에서 미종료 회의를 다시 열고 동의·장치를 확인한 뒤 **청크 복구 후 녹음 재개**를 누른다. 청크 복구만 누르면 업로드만 동기화하고 회의를 종료하지 않는다.
- 녹음 종료 및 저장 또는 회의 종료를 누른 녹음은 복구 후 저장을 완료한다. 이미 종료·완료한 회의를 다시 여는 기능은 제공하지 않는다.
- 이어 녹음 파일 병합에는 API 실행 환경의 FFmpeg가 필요하다(Docker 이미지 포함). 병합 실패 시 청크 복구로 재시도한다.
