# 02. 사용자 흐름과 화면 상태

현재 앱은 MOCK/LOCAL_RECORDING/LIVE 흐름을 제공한다. LIVE의 실제 전사·교정·요약은 연결됐으며, 공급자 품질과 비용은 별도 유료 POC 대신 사용자가 같은 웹앱에서 확인한다(ADR-021). API 계약은 [05](05-API-CONTRACT.md), 남은 검증은 [08](08-IMPLEMENTATION-PLAN.md)을 따른다.

## 접속
최초 한 번 기존 접속 토큰으로 소유자를 확인하고 아이디·비밀번호를 등록한다. 이후에는 아이디·비밀번호로 로그인하며 로그인 유지 선택 시 서버 재시작 후에도 최대 30일 접속한다. 공개 회원가입은 제공하지 않는다. 로그아웃·만료 시 재로그인하며, 백업 복원 후에는 계정을 유지하고 다시 로그인한다.

## 시나리오 A — 실시간 회의
1. 대시보드에서 `새 회의` 선택.
2. 제목·주제(MES/ERP/IT/일반/신규)·입력장치·화자 구분·월 예산 잔여량 확인. 승인된 용어 목록 미리 로드.
3. 녹음/외부 API 전송 고지 및 참석자 동의 확인, 마이크 권한 승인.
4. `시작` → 브라우저 녹음 청크 저장 **병행** + 백엔드 WebSocket relay → Deepgram Live STT.
5. 화면: 흐릿한 임시 텍스트 → 확정 원문 → 비동기 Sol 교정. 화자 ID는 오면 붙이고 변경될 수 있음. 미확정/겹침 시 표시.
6. 사용자는 정정/메모/예산 및 연결 상태 확인. 오류 시 `녹음 계속 / 실시간 전사 일시 중단` 안내.
7. `종료` → 녹음 청크/전사 이벤트 정합성 검사, 누락 구간만 별도 재처리 여부 제안, 최종 요약 생성.
8. 사용자가 원문 듣기·화자 라벨 교정·숫자 검토·결정사항 승인 후 저장/내보내기.

## 시나리오 B — 기존 녹음 업로드
- 파일 선택 → 형식 검사 → 원본 저장 → **선택한 공급자의 배치 전사** → Sol 요약. 현재 미구현이며 실시간 경로 연결 후 필요에 따라 진행한다.

## 화면
현재 경로는 `apps/web/src/App.tsx`를 기준으로 한다. 미인증 시 같은 주소에서 로그인 화면을 먼저 표시한다.

| 화면 | 현재 역할 |
|---|---|
| `/`, `/meetings` | 회의 목록·검색·제목 변경·삭제 |
| `/meetings/new` | 제목·주제·Mock/마이크 녹음 선택 |
| `/meetings/:id/live` | 가상 전사 또는 로컬 녹음, 전사 검토·가상 요약·재생·내보내기 |
| `/topics` | 주제·용어·별칭 관리와 후보 승인/거절 |
| `/usage` | 사용량·예산·보관 설정과 검토 |

별도 `/meetings/:id/review`, `/meetings/:id`, `/settings` 화면은 현재 제공하지 않는다. 실제 전사·화자 검토·AI 옵션은 통합 구현에서 필요한 화면에 연결한다.

## 발언 상태와 업데이트
- `PARTIAL`: 동일 provider sequence/event 식별자로 UI에서 덮어씀; DB 저장은 선택적/짧은 보관.
- `FINAL`: provider 최종 이벤트가 오면 원문을 1회 불변 저장.
- `CORRECTION_PENDING`: 비동기 LLM 검사 중; 기존 화면/녹음 영향 없음.
- `CORRECTED`: 승인/자동 적용 가능한 안전한 변경만 반영하며 원문 보존.
- `REVIEW_REQUIRED`: 중첩 발언, 모호한 고유번호, 화자 불확정 등.
- 사용자 수정 시 `revision`을 증가시키고 LLM의 늦은 응답이 덮어쓰지 않음.

## 예외
- 두 사람이 동시에 발언: 두 발언의 타임스탬프 중첩 가능; 완전 분리를 보장하지 않음.
- 말더듬: 텍스트 클린업은 표시 계층, 원문 저장.
- 음성 네트워크 장애: 녹음 청크 별도 유지, 재연결 뒤 빠진 구간만 재요청.
- 브라우저 종료/절전: 녹음 보존 범위는 브라우저 저장 구현과 운영체제 상태에 따라 다름; 한계 UI 고지.
- 사용자 예산 초과: 외부 전사 신규 연결 전에 알림/차단; 이미 시작한 회의의 녹음은 계속할 수 있음.

## 연결 실패와 녹음 재개 (2026-10-29)

- 상단은 AI 연결, 녹음 영역은 원본 보관·서버 업로드 상태다. 업로드 성공이 AI 연결 성공을 뜻하지 않는다.
- 월 예산 부족 등은 안내 문구로 표시한다. 사용량·예산을 새 탭에서 수정한 뒤 **AI 전사 다시 연결**을 누르면 마이크 녹음을 유지하며 새 전사를 시작한다. 소켓 단절은 지수 지연으로 자동 재시도한다.
- 연결되지 않은 음성 구간은 현재 화면에 별도로 표시하며 자동 재전사하지 않는다. 이 구간 표시는 화면 상태로, 새로고침 후 유지하지 않는다.
- 새로고침은 마이크를 중단한다. 같은 브라우저에서 미종료 회의를 다시 열고 동의·장치를 확인한 뒤 **청크 복구 후 녹음 재개**를 누른다. 청크 복구만 누르면 업로드만 동기화하고 회의를 종료하지 않는다.
- 녹음 종료 및 저장 또는 회의 종료를 누른 녹음은 복구 후 저장을 완료한다. 이미 종료·완료한 회의를 다시 여는 기능은 제공하지 않는다.
- 이어 녹음 파일 병합에는 API 실행 환경의 FFmpeg가 필요하다(Docker 이미지 포함). 병합 실패 시 청크 복구로 재시도한다.
