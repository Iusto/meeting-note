남은 검증은 실제 디스크 포화/절전·변경 이미지 재배포와 외부 공급자 품질이다. 실비 POC는 별도 승인 전 실행하지 않는다.

25일 인증 보강: 최초 토큰 확인 후 단일 소유자 계정·12시간/선택적 30일 DB 세션을 도입했다. 로그인·등록과 연결 시작/폐기의 경합을 하나의 프로세스 내 잠금으로 보호하고 트랜잭션 완료 후 연결을 종료한다. 만료 연결은 30초 주기로 확인한다. 정리 실패가 인증 응답으로 전파되지 않으며 진단에는 예외 클래스만 기록한다. 최초 브라우저 실패 2건은 누락된 Origin 헤더와 개발 서버 HMR 연결로 확인해 수정했다.

이번 인증 변경의 독립 코드 재검토는 APPROVE, 구조 검토는 CLEAR로 종합 APPROVE다. 경합 테스트에서 실제 잠금 대기 진입을 확인하고, 공급자 종료가 실패해도 DB stream/meeting 정리와 소켓 닫기를 각각 수행하는 회귀를 추가했다. 단일 프로세스의 현재 Fake 공급자 범위이며 실제 공급자 활성화 승인을 뜻하지 않는다. Java 전용 정적 분석은 별도이며 컴파일·JUnit과 웹 lint·TypeScript 검사를 수행했다. Docker daemon 접근 실패로 변경 이미지는 아직 배포하지 않았다.

추가 통합 시험은 API 키를 사용하지 않았다. 다화자 final의 두 번째 DB 삽입을 실패시켜 전체 발언과 speaker가 롤백되는지 H2·실제 PostgreSQL에서 확인했다. final 이후 늦은 partial, 전사/승인 용어 변경 중 AI 지연 응답, 거절된 응답·잘못된 usage·예약 초과·무응답·호출자 취소도 포함했다. 서버 로그는 `.tools/ai-integration-full.log`에 있다. 웹 15개와 lint·타입 검사·빌드도 재통과했다.

21일 보강에서는 활성 세션 단일화·재연결 offset·Metadata ID·정리 실패 처리를 추가했다. 구조 리뷰에서 지적한 재시작 후 claim/예약 잔류와 저장 timeout 후 늦은 쓰기 충돌도 수정했다. 선택적인 시작 복구의 PostgreSQL session advisory lock 경쟁, linked/unlinked RESERVED/DISPATCHED 대사, interrupt를 무시한 저장 worker 종료 전 재연결 차단을 포함해 관련 40개 시험을 01:22 KST에 통과했다. 초기 시험의 FK 삭제 순서·예산 초기화 오류를 수정했고 재시험에서 실패/오류가 없었다.

21일 추가 보강에서는 V8 이전 claim 없는 Deepgram stream의 시작 복구 누락을 실패 시험으로 재현하고 수정했다. 관련 14개 시험에서 기존 완료 stream과 다른 공급자 기록 보존·반복 실행을 확인했다. 독립 실행 POC 명령은 기본 dry run, 명시적 실행/합성 자료 승인/시간·금액 제한, 결과 파일 덮어쓰기 거부, 오류 비밀정보 제거를 적용했다. 가짜 Java를 쓰는 PowerShell 래퍼 시험 2개와 키 없는 runner 시험 17개를 통과했다. Deepgram 결과의 빈 단어 배열로 문자 수 제한을 우회하는 크기 증가도 실패 시험으로 재현하고 누적 JSON 바이트·최종 4MiB 제한을 추가했다.

21일 독립 구조 재검토는 새 명령·시작 복구 범위에서 WATCH였다. 코드 리뷰의 연결 대기 취소 누락(HIGH), 큰 OpenAI 결과의 비용 증거 소실·결과 경로 교체 경쟁(MEDIUM 2건)은 회귀 시험의 실패를 확인한 뒤 수정했다. 연결 취소 전파·늦은 연결 종료, 최초 파일 handle 유지, 큰 구조화 출력만 생략하고 request ID·usage·추정비용 보존을 추가했다. 재검토에서 해당 3건은 해소됐다. 이후 관련 17개·전체 176개 시험을 통과했으나 전체 코드 승인으로 계산하지 않는다.

22일 잠금 유실 보강: 시작 복구 단위 10개·가짜 WebSocket/DB 통합 19개·transport 12개, 총 41개가 통과했다. 별도 실제 PostgreSQL 16개에서 전용 backend 강제 종료, 유실 후 재획득·예약·연결 거절, 후속 인스턴스의 APP_RESTART/UNCERTAIN 복구를 확인했다. 가짜 transport의 abort 예외와 연결 성공 공개 직전 유실도 포함한다. DB/driver 경고는 예외 종류·SQLState만 남기며 메시지의 비밀정보는 기록하지 않는다. 첫 PG 시험의 누적 원장 데이터와 전체 시험에서 드러난 비동기 정리 대기 누락은 테스트를 수정해 재검증했다.

22일 독립 두 리뷰의 재검토 결과는 코드 COMMENT(미해결 수정 요청 0), 구조 WATCH이며 종합 COMMENT다. 제공된 진단 backend는 TypeScript/grep뿐으로 Java LSP 검증은 하지 못했다. 감시/로컬 차단을 분산 쓰기 보장으로 계산하지 않는다. 소유권 확인 뒤 이미 시작된 저장과 후속 소유자의 경합은 트랜잭션 소유권 검증으로 막아야 하며, 운영 공급자 활성화는 이 보호와 실제 POC 전까지 차단한다. lifecycle monitor 안의 future 성공 통지가 호출자 callback을 실행할 수 있는 점도 운영 연결 전 분리해야 한다. 서버 전체 정적 분석·실제 공급자의 취소/재시작/시간 제한은 별도다.

사용자가 휴대폰의 Tailscale HTTPS 로그인과 실제 녹음 파일 재생을 확인했다. `.bin` 다운로드는 서버 응답의 고정 파일명 문제로 확인해 녹음 MIME에 맞게 `.webm`/`.ogg`로 수정했다. 저장 파일·인코딩은 변경하지 않았다. 추가 매개변수 시험의 로그인 제한 충돌은 테스트 준비에서 기존 SessionService를 사용해 해결했고, 파일 시험의 임시 경로는 Surefire `argLine`으로 작업 폴더를 지정했다. 유료 호출은 없으며 운영 반영은 남아 있다.

첫 4시간 시험은 지속시간 검사에 실패했다(14,396,090ms, 기준 14,398,000ms). 청크 단절 없이 해시·별도 재생은 확인했으나 전체 통과로 계산하지 않았다. 테스트의 Node 벽시계와 브라우저 단조 시계 혼용을 수정하고 타입 검사·재시작·1분 시험을 통과한 뒤, 19일 00:30~04:30 KST의 4시간 재시험이 통과했다. 브라우저 경과 14,400,019.3ms, 기록 길이 14,400,058ms이며 기존 2초 허용치는 유지했다. 실패/통과 보고서와 녹음은 로컬 증거로 보존하고 소유 임시 DB·프로세스는 정리했다.

## 테스트 계층
- 백엔드: JUnit 5, Spring Boot Test, 기본 H2와 선택 실행하는 실제 PostgreSQL 임시 DB, WebSocket/HTTP 가짜 공급자. PostgreSQL 시험 계정에는 임시 DB 생성 권한이 필요하다.
- 프론트: Vitest + React Testing Library; 최소 주요 UX E2E는 Playwright.
- 외부 API: 키 없는 Mock/녹음 fixture로 기본 테스트. **명시적 예산 opt-in**인 별도 POC만 실비 호출.

## 품질 게이트 1 — Nova-3 POC (Phase 1)
동일한 **가상** 한국어 MES 샘플(2~4인, 5~15분; 단일 마이크, 말 겹침, 키워드 변형)로 측정한다.
| 지표 | 측정법/판단 |
|---|---|
| 실시간성 | 첫 자막 지연 p50/p95, 발언 종료→final 지연, 실시간 누락 |
| 한국어 CER/WER | 사람이 교정한 참조 전사본과 비교; 규칙 통일 |
| 전문용어 | LOT/BOM/WIP recall/precision, keyterm ON/OFF 비교 |
| 화자 구분 | DER 또는 화자 전환 오류 건수, overlap별 별도 기록 |
| 원문 보존 | final·녹음 fragment 누락 0건 목표, 중복 이벤트 멱등 |
| 비용 | 실 청구 오디오 분수 / 추가 옵션 분당 단가 / 세션 재연결 누적 |

**POC를 통과하지 못하면** Deepgram 채택 확정 금지. 같은 오디오로 AssemblyAI 또는 다른 STT 후보와 비교하고 ADR 수정. 특定 사업자의 광고 벤치마크를 한국어 품질의 증거로 삼지 않는다.

실험 결과는 실행 후 이 문서에 기록한다. 일시·입력 환경·마이크/코덱·오디오 길이/화자 수·모델/파라미터/라이브러리·relay 버전·지역/네트워크/브라우저, 각 지표의 기준·측정값·판정, 오류 구간의 실제 발언/API 결과/조치, GO/NO-GO와 이유·후속 ADR을 남긴다. 실행 전 값은 미측정이며 추정 성능을 채우지 않는다.

## 품질 게이트 2 — 실사용 스트레스 (Phase 4)
- 15분 → 60분 → **4시간** 연속 녹음·전사·다중 세션 재연결.
- 연결 끊김/브라우저 refresh/절전/서버 프로세스 재기동/디스크 부족을 각각 테스트.
- `PARTIAL` 이벤트가 역전·중복·누락되어도 확정 데이터가 오염되지 않는지 확인.
- 말더듬, 발언 정정, 사전 미등재 전문용어, 중요 LOT ID 오독, 비슷한 화자 목소리, 동시 발언.

## 회귀 케이스
| 입력 상황 | 기대 |
|---|---|
| MES: '로떠번호' | LOT 교정 **제안 가능**, 항상 자동 치환 아님 |
| 복권: '로또 번호' | LOT로 오교정하지 않음 |
| LOT `A240815-03` vs STT `...08` | 불일치/불확실 → 검토, 무근거 자동 확정 금지 |
| '금요일... 아니 목요일' | 최종 결정 목요일, 정정 과정 원문 유지 |
| 2인 동시발언 | overlap/UNKNOWN 가능, 허위 화자 식별 금지 |
| 사용자 수정 후 LLM 지연 도착 | `user_locked` 유지, 자동 덮어쓰기 금지 |
| API 연결 실패 | 로컬 녹음 지속, 상태/재연결/누락 재처리 |
| 장시간 데이터 | 4시간 녹음 연결/저장 상태·비용 확인 |

## 목표(실측 성능 보장 아님)
- 첫 자막 지연 p95 ≤ 3초를 첫 목표로 두되 실측 실패 시 UI/모델/네트워크 최적화 또는 목표 재설정.
- 4시간 원음 저장 누락 0건; 불가 시 실패 범위 명시하고 개선 전까지 실사용 금지.
- 한국어 정확도와 화자 성능의 POC 합격선은 기준 샘플을 만든 후 **사용자와 결정**.

## 평가 데이터 취급
실제 회사 회의 음성은 사내 정책과 참가자 동의 확인 전 클라우드 API에 전송하지 않는다. 평가용 자료는 합성 음성/동의된 녹음만 사용하고 Git에 개인 음성을 커밋하지 않는다.
