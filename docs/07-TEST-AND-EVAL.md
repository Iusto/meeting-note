인증 변경의 이전 독립 리뷰는 코드 APPROVE·구조 CLEAR였다. 공급자 준비 단계의 이전 리뷰는 코드 COMMENT·구조 WATCH였으며 현재 LIVE 연결 검증과 구분한다. Java 전용 정적 분석은 실행하지 못했으며 Maven 컴파일·JUnit과 웹 lint·TypeScript 검사를 수행했다.

### 실패에서 수정한 사항

- **늦은 마이크 시작의 시간축:** 회의 시작과 마이크 시작 사이 간격을 초기 PCM offset에 포함하고, 재연결·누락 구간에도 같은 기준을 적용했다. 단위 테스트로 늦은 시작과 재연결을 확인했다.
- **브라우저 검증의 일시 실패:** 설정 조회가 Chrome `ERR_NO_BUFFER_SPACE`로 실패해 스트림 대기가 시간 초과됐다. 코드·제한 시간 변경 없이 격리 환경에서 전체 18개를 다시 실행해 통과했다.
- **4시간 시험의 시계 혼용:** 첫 시험은 기록 길이 14,396,090ms로 최소 기준 14,398,000ms에 미달했다. 테스트의 Node 벽시계·브라우저 단조 시계 혼용을 수정하고, 기존 2초 허용치를 유지한 재시험에서 통과했다. 앱 코드는 바꾸지 않았다.
- **다운로드가 `.bin`으로 표시:** 고정 응답 파일명을 녹음 MIME에 맞는 `.webm`/`.ogg`로 수정했다. 알 수 없는 형식은 `.bin`을 유지하며 저장 파일·인코딩은 변경하지 않았다.

## 테스트 실행

기본 설정은 Mock이며 실제 공급자 키를 사용하지 않는다. 운영 DB·녹음 경로와 분리해서 실행한다.

| 계층 | 위치·명령 | 준비 사항 |
|---|---|---|
| 서버 | `apps/api`: `.\mvnw.cmd test` | JDK 21. 기본 H2, 가짜 HTTP/WebSocket 공급자 |
| 웹 | `apps/web`: `npm ci`, `npm test`, `npm run lint`, `npm run build` | Node.js, 타입 검사는 build에 포함 |
| 브라우저 | [E2E 실행 안내](../tests/e2e/README.md) | 별도 앱·DB·브라우저. 장시간/재시작 시험은 명시적 opt-in |
| 운영 | 저장소 루트: `python -m unittest discover -s tests/ops -p 'test_*.py' -v` | Python. 실제 PostgreSQL 복원은 별도 opt-in |
| 평가·비용 | [운영 도구 안내](../scripts/README.md#offline-poc-evaluation) | 합성 JSON과 명시적 단가. API 호출 없음 |

실제 PostgreSQL 검증은 `CREATEDB` 권한이 있는 유지관리 DB 연결을 지정한다. `apps/api`에서 설정 후 Maven 테스트를 실행한다.

```powershell
$env:APP_TEST_DATABASE_URL='jdbc:postgresql://localhost:5432/postgres'
$env:APP_TEST_DATABASE_USER='ai_meeting'
$env:APP_TEST_DATABASE_PASSWORD='<테스트 DB 비밀번호>'
.\mvnw.cmd test
```

테스트는 `ai_meeting_test_<임의 ID>` DB를 만들고 연결 풀 종료 후 삭제한다. 지정한 유지관리 DB의 회의 테이블에 자료를 쓰지 않는다. 백업·복원의 실제 PostgreSQL 왕복 조건은 [운영 안내](../scripts/README.md#backup-and-restore)를 따른다.

## 실제 AI 통합 검증

ADR-021에 따라 별도 유료 POC를 선행하지 않고 웹앱의 녹음→전사→교정→요약 경로를 검증한다. 먼저 가짜 공급자 통합 시험을 통과하고, 실제 호출에는 승인된 자료·명시적 opt-in·시간 제한·모든 재시도를 포함한 총예산을 적용한다. 현재 실제 실행 결과는 없다.

1. 짧은 승인된 한국어 샘플로 실시간 자막·화자·원문 저장·교정·요약을 한 번의 흐름에서 확인한다.
2. 연결 실패·예산 소진·취소 시 원본 녹음 유지, 명시적 오류 표시, 추가 호출 중단을 확인한다.
3. 용어·숫자·날짜·발언 정정과 요약 근거를 사람이 확인한다. 품질이 낮은 구간을 먼저 수정한다.
4. 일시·자료 길이/화자 수·코덱·모델/옵션·브라우저/네트워크·사용량·추정비용/확정 청구·오류와 조치를 이 문서에 기록한다.

| 지표 | 측정 방법 |
|---|---|
| 첫 자막·final 지연 | 음성 입력부터 화면 표시까지 p50/p95. 공급자 receive 시각만으로 전체 지연을 주장하지 않음 |
| 한국어·전문용어 | 사람이 정렬한 참조 전사의 CER/WER, LOT/BOM/WIP 인식·오교정 사례. 추가 유료 비교는 필요할 때만 수행 |
| 화자 | 사람이 대응시킨 라벨의 오류·미확정·겹침 기록. 단순 불일치율을 DER로 표기하지 않음 |
| 원본·정합성 | 최초 final 불변, 청크 누락/중복, 녹음 해시와 재생, 사용자 수정 후 늦은 응답 보호 |
| 비용 | 실제 오디오 분수·입출력 토큰·재시도·가격 버전 기록. 추정액과 확정 청구액 구분 |

첫 자막 p95 3초와 4시간 원음 저장 누락 0건은 목표다. 실제 품질이 사용자 검토로 감당 가능한지 확인하며, 기능 연결과 한국어 품질 검증을 별도로 표시한다.

## 장시간·장애 검증

- 짧은 통합 확인 후 필요에 따라 15분→60분→4시간으로 늘린다. 녹음만의 4시간 통과를 STT 동시 연결 통과로 계산하지 않는다.

## 평가 자료 취급

회사 회의는 사내 정책과 참가자 동의 확인 전 외부 API에 전송하지 않는다. 합성 음성 또는 전송이 허용된 녹음만 사용하고, 음성·전사·자격 증명은 Git에 커밋하지 않는다. 입력 계약 예제의 합성 텍스트와 실제 음성 결과를 혼동하지 않는다.
