# 08. 개발 계획과 구현 상태

기준일: 2026-10-26. 각 구현 범위는 관련 테스트를 통과한 뒤 다음 작업으로 진행한다. 실행 결과와 한계는 [07 테스트·검증](07-TEST-AND-EVAL.md)에 기록한다.

| 구분 | 상태 |
|---|---|

기본 실행은 `MOCK / LOCAL_RECORDING`이며 유료 호출은 꺼져 있다. 서버를 `-EnablePaidAi`로 배포하고 월 예산을 양수로 저장하면 `LIVE`와 OpenAI 요청을 선택할 수 있다.

## 다음 작업 — 실사용 검증과 배포

2026-10-25 사용자 요청으로 **별도 유료 POC를 먼저 수행하는 순서에서, 실제 웹앱에 연결하고 같은 경로로 통합 검증하는 순서로 변경**했다(ADR-021). 개인 사용 중 드러난 품질 문제는 반복 개선한다. 기존 독립 POC 명령은 선택적 진단 도구로 남기며 필수 선행 단계로 사용하지 않는다.

1. **변경 이미지 반영:** `start-private.ps1 -EnablePaidAi`로 빌드·배포하고 로그인·마이크·인증된 WSS·AI 가용 표시를 확인한다. 현재 에이전트 세션은 Docker 엔진을 찾지 못하고 Tailscale 제어 접근이 거절되어 운영 배포를 실행하지 못했다.
2. **사용자 실사용:** 월 예산을 작은 양수로 저장한 뒤 승인된 회의에서 녹음→전사→교정→요약·용어 후보를 확인한다. 실제 품질·사용량·비용은 07에 기록한다.
3. **회귀 수정:** 실사용에서 드러난 품질·누락 문제만 같은 경로의 회귀 테스트로 고친다.

소스 연결 완료와 실제 공급자 품질·운영 배포 완료를 구분한다. 자동 테스트 통과만으로 한국어 인식률·화자·지연·청구액을 주장하지 않는다.

## Phase별 범위

Phase 번호는 기존 계획과의 추적을 위해 유지한다. 2026-10-16부터 공급자 독립 기능을 먼저 구현했으므로 번호순으로 전부 완료된 상태는 아니다. Phase 1의 실측은 이제 웹앱 통합 검증 안에서 수행한다.

## 실사용을 막는 조건

- 비용 상한이 적용되지 않거나 재시도가 무제한인 경우.
- 원본 녹음·확정 전사를 훼손하거나 누락을 감지할 수 없는 경우.
- 인증·키 보호·중요 고유번호 보호가 깨지는 경우.
- 품질 오류가 사용자 검토·수정으로 감당하기 어려운 경우. 이때 같은 짧은 샘플로 대안을 비교하고 ADR을 갱신한다.

한국어 정확도·화자 품질·첫 자막 p95 3초는 검증 대상이다. 초기 목표 미달만으로 별도 대규모 비교 실험을 자동 실행하지 않는다.
