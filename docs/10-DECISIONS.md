## 웹앱 통합 검증으로 순서 변경

독립 POC와 웹앱 검증을 연속 실행해 같은 음성을 다시 과금하는 대신, 실제 사용할 경로에서 검증한다. 기존 POC 도구는 파라미터·연결 문제를 좁힐 때만 선택적으로 사용한다. 가짜 공급자 회귀를 먼저 통과하고 실제 실행의 모든 재시도는 앱에 설정한 월·회의 상한에 누적한다.

품질 미달은 사용자 검토와 수정으로 개선하되, 키 노출·인증 우회·무제한 비용·원본 손상은 허용하지 않는다. 이 결정은 실측 완료나 유료 설정 활성화를 뜻하지 않는다.

## ADR-022 — 실사용 연결 복구와 회의당 예산 설정 (ACCEPTED, 2026-10-29)

사용자 실사용에서 월 예산 0으로 전사가 차단됐으나 원인이 표시되지 않았고, 예산을 변경해도 전사를 재시도할 수 없었다. 녹음과 전사 상태를 분리하고, 소켓 단절의 자동 재연결과 공급자 오류 후 수동 재연결을 제공한다. 재연결은 새 오디오부터 처리하며 누락 구간을 표시하고 기존 오디오를 자동 재과금하지 않는다.

회의당 금액은 `app_settings.per_meeting_budget_usd`로 이동한다(V11, 초기값 3 USD). 월 예산과 별도로 화면에서 수정하며 새 STT/LLM 요청부터 적용한다. 실제 서버 배포에서는 DB 값이 기존 `AI_MAXIMUM_MEETING_USD` 환경변수보다 우선한다. 기본 유료 OFF와 누적 예약·시간 제한은 유지한다.

새로고침 후 같은 브라우저의 미종료 녹음은 청크 번호·형식을 유지해 재개한다. 독립 MediaRecorder WebM 세션은 원본 청크의 해시를 검증하고 Docker에 포함한 FFmpeg로 remux한다. 파일을 단순 이어 붙이지 않으며, 병합 실패 시 원본 청크와 미완료 상태를 남겨 재시도한다. 중단 동안의 소리와 브라우저 종료 직전 미저장 청크는 복구할 수 없다. Ogg 이어 녹음은 지원하지 않는다.

WebM 병합 방식의 근거: [FFmpeg 공식 concat demuxer 계약](https://github.com/FFmpeg/FFmpeg/blob/master/doc/demuxers.texi). 동일 코덱·타임베이스를 유지하며 원본 청크는 수정하지 않는다.
